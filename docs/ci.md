# Первые тесты и CI

Это учебный проект Школы 21. Проверки добавлены для существующих скриптов;
они не означают, что весь проект полностью протестирован.

## Запуск локально

Из корня репозитория:

```bash
python3 -m unittest discover -s tests -v
find src -type f -name '*.sh' -print0 | xargs -0 -n 1 bash -n
shellcheck -x -P SCRIPTDIR src/01/main.sh src/01/check_param.sh src/05/validate.sh
```

Нужны Python 3, Bash и установленный ShellCheck. Тесты используют стандартную
библиотеку Python (`unittest` и `subprocess`), дополнительных Python-пакетов нет.
Полные скрипты сбора метрик рассчитаны на Linux; тесты первой части и валидатора
пути можно запустить также на macOS.

## Что проверяется

- Первая часть: точный вывод текста, пробелов, кириллицы, пустой строки,
  обратных слешей и аргументов `-n`/`-e`; отклонение целых и дробных чисел;
  ошибка при отсутствии аргумента или передаче нескольких.
- Пятая часть: валидатор принимает существующий каталог с завершающим `/`,
  включая пробелы в пути; отклоняет файл, отсутствующий каталог, неверное
  число аргументов и путь без завершающего `/`.
- Успех и ошибка проверяются по коду возврата, stdout и stderr.
- Все `.sh` в `src` проверяются командой `bash -n` на синтаксические ошибки.
- ShellCheck проверяет только первую часть и валидатор пятой части.

`unittest` показывает 8 тестовых методов; внутри некоторых методов несколько
сценариев запускаются через `subTest`. Каждый запуск Bash ограничен 5 секундами.
Временные каталоги создаются и удаляются автоматически; реальные данные не меняются.

## Как работает GitHub Actions

Workflow `.github/workflows/ci.yml` запускается при push, pull request или вручную.
Он получает код, проверяет синтаксис, запускает ShellCheck и тесты.
Ошибка любого шага делает job красным. Подробности доступны во вкладке Actions.
Workflow имеет только право чтения кода и не использует секреты.

Это CI: автоматические проверки изменений. Развёртывания на homelab здесь нет.
Для GitHub Actions использованы доступные на runner Bash и Python 3.

## Найденное исправление

Ранее `echo "$param"` воспринимал `-n` как опцию вместо текста. Тест точного
вывода воспроизводит ошибку. `printf '%s\n' "$param"` выводит аргумент буквально.

## Границы покрытия

Пока не проверяются сбор системной информации, сохранение отчёта, цветовые
схемы, чтение конфигурации и правильность отчёта о файловой системе.
В частности, тест валидатора пути не проверяет весь сценарий пятой части.
ShellCheck ещё не применяется ко всем остальным модулям. Следующее расширение
покрытия — отдельная задача после изучения текущих проверок.
